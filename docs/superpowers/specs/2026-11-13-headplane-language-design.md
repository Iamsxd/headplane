# Headplane 中英文切换

用户要求现有后台可切换中英文。右上角显示语言选择，选项为“简体中文”和“English”，默认继续中文。切换提交后完整刷新当前页面，保留路径与查询参数，以浏览器 Cookie 记忆一年；不同浏览器互不影响。

实现选择（由执行者决定）：复用已部署的中文 UI 和官方 0.8.2 英文 UI，分别编译同一版本的两套视图。一个 Node 进程、一个后端 context、同一数据库/登录/Headscale 客户端/后台任务；HTTP 请求依据经校验的 language Cookie 选择视图处理器。静态资源合并并检查同名文件一致，避免切换后旧页面资源失效。英文处理器必须不初始化配置、数据库、监听端口或后台服务。

比较过逐条运行时 i18n 和双视图构建。前者需要重新抽取全部文案并修改模块级常量、服务端消息和客户端状态，改动范围更大；后者直接保留已验证的中文与官方英文，仅需语言偏好、共享处理器工厂和发布构建支持。拒绝 DOM 文本替换或浏览器翻译，以免覆盖用户数据或生成混合语言。

新语言 POST 路由沿用原版请求处理与 CSRF 校验。只接受 zh-CN/en，Cookie 为 Secure、HttpOnly、SameSite=Lax，Path=/admin。跳转目的地限制在 /admin 内，无外部或控制字符跳转。无合法 Cookie 时中文，不依赖 Accept-Language 自动覆盖用户选择。保留权限角色、命令、表单值、API/配置键、节点身份与安全限制。

验证覆盖：Cookie 缺失/损坏/非法、记忆和切回、当前路径和过滤参数、危险重定向、并发两种语言、设备/用户/ACL/DNS/设置及弹窗、未授权请求、SSR/客户端一致、共享数据库与单例后端、既有服务和备份。候选隔离数据测试后备份切换固定镜像，失败回退。

Ruling：用户已明确要求对既有后台加语言切换，入口和默认值属于常规实现选择；按既有授权直接实现并部署，不额外要求设计审批。当前目录不是 Git 仓库，沿用独立服务目录、上游对照和服务器候选构建目录。
